# 별첨1. 스토리/시나리오 작가 가이드라인

이 문서만 읽으면 시나리오를 처음부터 끝까지 쓸 수 있도록 만든 가이드다. 게임 구조에 대한 배경 지식은 기획서 v2를 참조하되, 작성에 필요한 내용은 여기에 전부 다시 적었다.

---

## 1. 먼저 알아야 할 게임 구조 (작가 관점 요약)

- 이 게임의 플레이어는 **말로** 플레이한다. 선택지를 클릭하는 게 아니라, 마이크에 대고 자유롭게 말하면 AI가 의도를 판정한다.
- 따라서 작가는 **"정답 대사"를 쓰는 게 아니라 "의도"를 정의한다.** "주말에 같이 갈래?"라는 문장이 아니라, "주말 약속을 제안하는 의도 + 그 의도를 나타내는 키워드들"을 쓴다.
- 자유 대화 구간의 캐릭터 대사는 AI(LLM)가 실시간 생성한다. 작가는 대사 전부가 아니라 **캐릭터의 말투(페르소나 시트)와 각 장면의 목적**을 쓴다.
- 대화가 늘어지지 않도록 모든 장면에는 **턴 상한**이 있고, 상한에 도달하면 호감도에 따라 자동으로 다음 장면으로 넘어간다. 이 "넘어가는 순간"을 어색하지 않게 만드는 대사도 작가의 몫이다.
- 스토리 골격은 고정이다: **일상(호감도 적립) → 사건 발생 → 변신(음성 주문) → 전투(말로 싸움) → 수렴 → 엔딩 4종.**

### 작가가 쓰는 것 / 쓰지 않는 것

| 쓰는 것 | 쓰지 않는 것 |
|---|---|
| 페르소나 시트 (캐릭터별 1장) | 자유 대화의 개별 대사 (LLM 몫) |
| 노드별: 목적, 오프닝 대사, 의도 3개, 탈출표, 폴백 대사 | 플레이어 발화의 모든 변형 |
| 변신 주문 전문 + 핵심 키워드 | 판정 로직, 수치 밸런스 세부 (기본값 제공됨) |
| 전투 페이즈별: 적의 압박 대사, 주문 3종, 컨텍스트 | |
| 엔딩 4종 본문, 컷씬 지문 | |

## 2. 작업 워크플로 (Claude 활용)

1. **페르소나 시트부터.** §6 양식대로 작성 — 이후 모든 것의 기준이 된다.
2. **노드 설계표를 표로 먼저.** JSON을 바로 쓰지 말고, Claude에게 이 가이드와 페르소나 시트를 주고 "노드 설계표(장면/목적/의도/탈출)"를 표 형태로 함께 만든다.
3. **표 → JSON 변환.** 표가 확정되면 Claude에게 §4의 스키마를 주고 변환을 맡긴다. 변환 프롬프트 예시:
   > "아래 노드 설계표를 첨부한 JSON 스키마(§4)에 맞춰 변환해줘. 필드를 임의로 추가·생략하지 말고, next가 가리키는 nodeId가 전부 실제 존재하는지 목록으로 확인해줘."
4. **개발자에게 전달.** 게임이 JSON을 읽는 순간 자동 검사(존재하지 않는 nodeId 참조, 필드 누락 등)가 돌고, 오류가 한국어 메시지로 출력된다. 오류가 나면 그 메시지를 Claude에게 주고 고치면 된다.

## 3. 파일 구성

| 파일 | 내용 |
|---|---|
| `scenario.json` | 노드 배열 — 스토리 본체. 이 문서의 대부분이 이 파일 작성법이다 |
| `characters.json` | 캐릭터 페르소나·표정 목록 |
| `config.json` | 턴 상한, 임계치 등 (개발자 관리 — 작가는 건드리지 않음) |

## 4. 노드 스키마 — 필드별 상세 설명

노드는 4가지 타입이 있다: `dialogue`(대화) / `cutscene`(연출·변신) / `battle`(전투) / `ending`(엔딩).

### 4.0 모든 노드의 공통 필드

| 필드 | 형 | 필수 | 설명 |
|---|---|---|---|
| `nodeId` | string | ✔ | 고유 ID. 규칙: `{챕터}_{장소나 상황}` 소문자·언더스코어 (예: `ch1_rooftop`). **한 글자라도 다르면 다른 노드로 취급되니 오타 주의** |
| `type` | string | ✔ | `dialogue` / `cutscene` / `battle` / `ending` |
| `scene.bg` | string | ✔ | 배경 파일명 (확장자 제외, 예: `bg_street_day`). 에셋 가이드의 파일명 목록과 일치해야 함 |
| `scene.bgm` | string | | BGM 파일명. 생략 시 이전 곡 유지 |

### 4.1 `dialogue` 노드 — 자유 대화 장면

| 필드 | 형 | 필수 | 설명·작성 팁 |
|---|---|---|---|
| `npc.id` | string | ✔ | 대화 상대 캐릭터 ID (characters.json의 id) |
| `npc.startEmotion` | string | ✔ | 노드 진입 시 표정: `neutral/happy/shy/upset/surprised` 중 하나 |
| `objective` | string | ✔ | **이 노드의 존재 이유 1문장.** LLM이 이 목적을 향해 대화를 능동적으로 끌고 간다. "플레이어가 ~하게 만든다" 형태로. 모호하면 대화가 산으로 감 |
| `opening` | string | ✔ | 노드 진입 시 캐릭터의 첫 대사 (고정 텍스트, 1~2줄). 장면 전환을 자연스럽게 여는 역할 |
| `llmContext` | string | ✔ | LLM에게 주는 상황 설명 2~4문장: 장소, 시점, 캐릭터의 현재 심경, 직전 사건. **⚠ 캐릭터가 모르는 정보(스포일러, 플레이어의 속마음)는 절대 넣지 않는다** — LLM이 대사로 흘린다 |
| `maxTurns` | int | ✔ | 자유 대화 턴 상한. 기본 5 (개발자가 시연 길이에 따라 일괄 조정 가능) |
| `intents[]` | array | ✔ | **의도 정의 3개** (아래 표) |
| `allowedFlags[]` | array | ✔ | 이 노드에서 세울 수 있는 플래그의 화이트리스트. intents의 setFlags에 쓴 것을 전부 나열 (안전장치) |
| `fallbackReplies[]` | array | ✔ | 인식 실패 시 캐릭터가 하는 말 2~3개. "미안, 잘 못 들었어" 류 — 캐릭터 말투로 |
| `exitOnMaxTurns[]` | array | ✔ | 턴 상한 도달 시 행선지 표 (아래 참조) |

**`intents[]`의 각 항목:**

| 필드 | 형 | 필수 | 설명·작성 팁 |
|---|---|---|---|
| `id` | string | ✔ | 의도 ID (영문, 예: `invite_weekend`) |
| `clickLabel` | string | ✔ | **클릭 폴백 모드의 선택지 버튼 문구.** 마이크가 죽으면 이게 그대로 선택지가 된다 — 반드시 작성 |
| `examples[]` | array | ✔ | 이 의도의 예시 발화 2개. LLM 판정의 기준 예시로 쓰인다 |
| `keywords[]` | array | ✔ | 매칭 키워드 5개 내외. **조사를 뗀 어간으로** ("좋아해"❌ → "좋아"✔), 짧고 발음이 분명한 단어로 |
| `affinityDelta` | int | ✔ | 호감도 변화 -3 ~ +3 |
| `setFlags[]` | array | ✔ | 세울 플래그 (없으면 `[]`). 플래그 이름은 §7의 플래그 사전에 먼저 등록 |
| `npcEmotion` | string | ✔ | 이 의도에 반응할 때의 표정 |
| `offlineReply` | string | ✔ | **오프라인 모드용 고정 응답 대사 1줄.** 네트워크가 죽으면 LLM 대신 이 대사가 나온다 — 모든 의도에 필수 |
| `next` | string \| null | ✔ | 매칭 즉시 이동할 노드. `null`이면 같은 노드에서 대화 계속 (호감도 적립용 의도) |

**`exitOnMaxTurns[]`:** 위에서부터 순서대로 평가된다. 마지막은 반드시 `default`.
조건식에 쓸 수 있는 것: `affinity`, 비교연산(`>=` `<` 등), `flags.플래그명`, `&&`. 예: `"affinity >= 60 && flags.asked_out"`

### 4.2 `cutscene` 노드 — 연출 / 변신 이벤트

| 필드 | 형 | 필수 | 설명 |
|---|---|---|---|
| `lines[]` | array | ✔ | 고정 연출 대사. 각 항목: `{ "speaker": "캐릭터ID 또는 narration", "text": "...", "emotion": "표정(선택)" }` |
| `incantationGate` | object | | **변신 주문 게이트.** 있으면 lines 재생 후 주문 낭독 이벤트 발생 (아래 표) |
| `next` | string | ✔ | 다음 노드 |

**`incantationGate`:**

| 필드 | 형 | 설명·작성 팁 |
|---|---|---|
| `displayText` | string | 화면에 크게 표시될 **주문 전문.** 낭독하기 좋게: 4~7어절, 리듬감 있게, 발음 쉬운 순우리말·한자어 위주, 숫자·외래어·받침 겹침 자제 (음성 인식률에 직결) |
| `requiredKeywords[]` | array | 채점 키워드 3~4개. 주문에서 가장 발음이 분명한 단어들 |
| `minMatch` | int | 성공 최소 매칭 수 (권장 2). 전부 매칭 = "완창"으로 강화 연출 + 보너스 |
| `maxAttempts` | int | 재도전 횟수 (권장 2) |
| `failLines[]` | array | 미달로 자동 진행될 때의 서사적 구제 연출 대사. **"실패해서 억지로 넘어감"이 아니라 이야기가 되도록** — 예: NPC가 손을 잡아 함께 외쳐준다. 이 대사가 이 게이트 작성의 핵심 |

### 4.3 `battle` 노드 — STT 대화형 전투

전투는 "기세(momentum)" 게이지 하나로 진행되고 패배가 없다. 결과는 승리 등급 S/A/B. 작가는 **적을 연기하는 대본**과 **페이즈별 주문**을 쓴다.

| 필드 | 형 | 필수 | 설명 |
|---|---|---|---|
| `enemy.id` / `enemy.name` | string | ✔ | 적 ID·표시 이름 |
| `phases[]` | array | ✔ | 페이즈 3개 (아래 표) |
| `next` | string | ✔ | 전투 후 수렴 노드 (등급은 자동으로 플래그 `battle_S/A/B`로 기록됨) |

**`phases[]`의 각 항목:**

| 필드 | 형 | 설명·작성 팁 |
|---|---|---|
| `phaseId` | string | 예: `p1` |
| `enemyPrompt` | string | 페이즈 시작 시 적의 압박 대사/행동 1~2줄. **플레이어가 "말로 받아치고 싶어지는" 도발이어야** 자유 대응이 산다 |
| `llmContext` | string | LLM에게 주는 페이즈 상황: 적의 상태, 무엇에 흔들리는지(약점), 이번 페이즈의 압박 내용. 플레이어가 약점을 찌르는 말을 하면 LLM이 높게 판정한다 — **약점 설정이 전투 재미의 절반** |
| `spell.displayText` | string | 이 페이즈의 공격 주문 전문 (변신 주문과 같은 작성 요령, 페이즈마다 다르게) |
| `spell.requiredKeywords[]` / `spell.minMatch` | array / int | 채점 키워드 3개 / 최소 매칭 (권장 2) |
| `guardLine` | string | 버티기 선택 시의 나레이션/대사 1줄 |
| `clickResponses[]` | array | 클릭 폴백용 자유 대응 대사 2개 (플레이어 대사 + 각각의 momentum 델타) |
| `maxTurns` | int | 페이즈 턴 상한 (권장 2~3) |
| `advanceAt` | int | 이 momentum에 도달하면 즉시 다음 페이즈 (권장 p1:60, p2:70) |

### 4.4 `ending` 노드

| 필드 | 형 | 필수 | 설명 |
|---|---|---|---|
| `endingId` | string | ✔ | `good / normal / bad / hidden` |
| `lines[]` | array | ✔ | 엔딩 본문 (cutscene의 lines와 동일 형식) |
| `gradeVariants` | object | | 전투 등급별 추가 대사 (선택): `{ "S": [...], "B": [...] }` — 등급이 서사에 남는 흔적 |

엔딩 진입 조건은 챕터3 마지막 노드의 `exitOnMaxTurns` 조건표에 쓴다 (엔딩 노드 자체에는 조건이 없다).

## 5. 완성 예시

현재 확정된 스토리(「심사역은 마법소녀가 되었다」 — 플레이어 한도윤, 마스코트 주노, 적 회색 망령)를 기준으로 한 **형식 예시**다. 대사는 자리표시용이니 작가가 교체한다.

### 5.1 dialogue 노드

```json

  "intents": [
    {
      "id": "listen_serious",
```

### 5.2 cutscene 노드 (변신 이벤트)

```json
{
  "nodeId": "ev_transform",
  "type": "cutscene",
  "scene": { "bg": "bg_hall_dark", "bgm": "bgm_crisis" },
  "lines": [
    { "speaker": "narration", "text": "복도의 빛이 잿빛으로 가라앉는다." },
    { "speaker": "juno", "text": "지금이야! 화면의 주문을 소리 내서 외쳐!", "emotion": "surprised" }
  ],
  "incantationGate": {
    "displayText": "반짝이는 별의 힘이여, 지금 여기에 — 변신!",
    "requiredKeywords": ["별", "힘", "변신"],
    "minMatch": 2,
    "maxAttempts": 2,
    "failLines": [
      { "speaker": "juno", "text": "괜찮아, 내가 같이 외쳐 줄게. 하나, 둘 —" },
      { "speaker": "narration", "text": "두 목소리가 겹치자, 빛이 응답했다." }
    ]
  },
  "next": "battle_wraith"
}
```

### 5.3 battle 노드 (1페이즈만 발췌)

```json
{
  "nodeId": "battle_wraith",
  "type": "battle",
  "scene": { "bg": "bg_hall_void", "bgm": "bgm_battle" },
  "enemy": { "id": "gray_wraith", "name": "회색 망령" },
  "phases": [
```

## 6. 페르소나 시트 양식 (캐릭터당 1장, characters.json에 수록)

| 항목 | 작성 내용 |
|---|---|
| `id` / `name` | 영문 ID / 표시 이름 |
| 정체·역할 | 2문장 이내 |
| 성격 핵심 3가지 | 형용사가 아니라 **행동 경향**으로 ("낯을 가리지만, 한번 마음을 열면 수다스럽다") |
| 말투 규칙 | 1인칭, 플레이어 호칭, 어미 습관, 문장 길이 경향 |
| 금기 | 절대 하지 않는 말·태도 (예: 존댓말 안 씀, 세계관 밖 지식 언급 금지) |
| **예시 대사 5개** | 상황이 다른 5개 — LLM이 말투를 배우는 가장 중요한 자료. 기쁠 때/삐졌을 때/진지할 때/얼버무릴 때/놀랐을 때 |
| 표정 목록 | `neutral, happy, shy, upset, surprised` (고정 — 에셋과 1:1) |

## 7. 작성 규칙 (반드시 지킬 것)

1. **선택지는 문장이 아니라 의도로.** 음성은 표현이 무한하다. 의도 + 예시 + 키워드로 정의한다.
2. **분기는 챕터 끝에서만.** 중간 노드는 호감도·플래그 적립 역할. 중간 분기를 늘리면 노드 수가 폭증해 예선 분량을 넘는다.
3. **모든 의도에 `clickLabel`과 `offlineReply` 필수.** 마이크와 네트워크가 죽었을 때의 생명줄이다.
4. **주문은 낭독용으로 쓴다.** 4~7어절, 리듬, 발음 쉬운 단어. 쓰고 나서 반드시 소리 내어 읽어 볼 것.
5. **키워드는 조사 없는 어간으로, 서로 다른 의도끼리 겹치지 않게.** 겹치면 오판정된다.
6. **캐릭터 대사는 80자 이내** (화면 읽기 15초). `llmContext`에도 "대사는 두 문장 이내" 습관을 전제.
7. **플래그 사전을 문서 맨 앞에 만들어 관리한다.** 등장 플래그 전부를 `이름 / 세워지는 곳 / 쓰이는 곳` 표로. 스펠링이 하나라도 다르면 다른 플래그다.
8. **`llmContext`에 스포일러 금지.** 캐릭터가 모르는 정보를 넣으면 LLM이 대사로 흘린다.
9. **강제 전환을 이야기로 포장한다.** 턴 상한 도달 시 첫 대사가 어색하지 않도록, exit 행선지 노드의 `opening`은 "대화가 끊기는 상황"을 자연스럽게 받아야 한다 ("아, 벌써 시간이…").
10. **BAD 엔딩도 완결된 이야기로.** 전투는 이미 승리한 상태다 — BAD는 관계의 아쉬움이지 게임 실패가 아니다.

## 8. 제출 전 셀프 체크리스트

- [ ] 모든 `next`가 실제 존재하는 `nodeId`를 가리키는가 (오타 포함)
- [ ] 타이틀에서 4개 엔딩 각각까지 도달 경로를 종이에 그릴 수 있는가
- [ ] 모든 dialogue 노드에 의도 3개 × (`clickLabel` + `offlineReply`)가 있는가
- [ ] `exitOnMaxTurns`의 마지막이 전부 `default`인가
- [ ] 주문 3종(변신 1 + 전투 페이즈별)을 소리 내어 읽어 봤는가
- [ ] 플래그 사전과 실제 사용처가 일치하는가
- [ ] 키워드가 의도 간에 겹치지 않는가
- [ ] `llmContext`에 스포일러가 없는가
