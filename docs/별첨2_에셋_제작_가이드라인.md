# 별첨2. Asset 제작 가이드라인

100% AI 제작 원칙에 따라 툴을 다음과 같이 배정한다. **캐릭터 = GPT Image / 배경 = 미드저니 / 음악 = Suno / SFX·UI = 코드 생성(Codex).**
배정 이유: GPT Image는 "같은 이미지에서 일부만 고치는" 편집 지시에 강해 캐릭터 표정 파생·일관성 유지에 적합하고, 미드저니는 배경 퀄리티와 스타일 통일(레퍼런스 재사용)에 강하다. Suno는 BGM·징글 전담.

---

## 1. 공통 규격과 원칙

| 종류 | 포맷 | 규격 | 파일당 용량 목표 |
|---|---|---|---|
| 배경 | webp | 1920×1080 | ≤ 500KB |
| 캐릭터 스탠딩 | png (투명 배경) | 1200×2000 고정 캔버스 | ≤ 800KB |
| 컷씬 일러스트 | webp | 1920×1080 | ≤ 700KB |
| UI 아이콘 | svg (코드 생성) | — | — |
| BGM | mp3 128kbps | 루프 60~90초 | ≤ 3MB |

- **총 용량 목표 30MB 이하** (GitHub Pages 로딩 속도). 생성 원본 → squoosh/ffmpeg으로 압축 후 커밋.
- **네이밍 규칙 (시나리오 JSON이 이 이름을 직접 참조한다 — 임의 변경 금지):**
  `bg_{장소}_{시간·상태}.webp` / `char_{id}_{emotion}.png` / `cut_{이벤트}_{번호}.webp` / `bgm_{용도}.mp3`
- **스타일 앵커:** 아트 스타일을 묘사하는 문장 1개(색감·선·조명·화풍)를 팀에서 확정하고, **모든 이미지 프롬프트 맨 앞에 동일하게 붙인다.** 이것이 게임 전체의 통일감을 만든다. 앵커 확정 전에는 어떤 에셋도 본생산하지 않는다.
- 라이선스: Suno·미드저니·GPT Image 생성물의 상업/대회 제출 허용 범위는 플랜·약관에 따라 다르다 — **해커톤 제출 규정과 각 툴 약관 확인 필요.**

## 2. 캐릭터 (담당: GPT Image)

### 2.1 필요 목록

| 대상 | 구성 | 수량 | 우선순위 |
|---|---|---|---|
| 주노 (NPC 마스코트) | 스탠딩 1포즈 × 표정 5종 (`neutral/happy/shy/upset/surprised`) | 5 | 필수 |
| 회색 망령 (적) | 전투 스탠딩 2상태 (`normal` / `weakened`) | 2 | 필수 |
| 한도윤 마법소녀 (플레이어) | 전투 스탠딩 1장 — **뒷모습 또는 반측면 구도 권장** | 1 | 필수 |
| 변신 컷씬 일러스트 | 영창 순간 1 + 변신 완료 1 | 2 | 필수 |
| 한도윤 평상시 모습 | 프롤로그용 | 1 | 컷 가능 (1인칭 유지 시 불필요) |
| 주노 추가 포즈 | 클라이맥스용 | 1 | 컷 가능 |

플레이어 전투 구도를 뒷모습으로 하는 이유: ① 표정 세트가 통째로 불필요해지고 ② "플레이어 = 나"의 1인칭 몰입이 유지되며 ③ 적과 대치하는 화면 구도가 저절로 만들어진다.

### 2.2 표정 파생 워크플로 (일관성 확보의 핵심)

1. **베이스 1장 생성:** 스타일 앵커 + 캐릭터 묘사로 `neutral` 스탠딩을 생성. 니샷(무릎 위), 정면~반측면, 단순한 포즈(팔 내림), 배경은 투명 지정(불가 시 단색).
2. **표정 4종 파생:** 베이스 이미지를 첨부하고 **"이 이미지에서 얼굴 표정만 ○○로 바꿔라, 몸·의상·구도는 그대로"** 편집 지시. **절대 처음부터 재생성하지 않는다** — 재생성하면 다른 사람이 나온다.
3. **배경 제거·정렬:** 투명 배경 확보 후, 5장을 전부 1200×2000 캔버스의 **같은 좌표**에 배치. 검수: 레이어를 겹쳐(오니언 스킨) 몸 윤곽이 픽셀 단위로 일치하는지 확인 — 어긋나면 표정 전환 시 캐릭터가 "튄다".
4. **적 2상태도 같은 방식:** `normal` 생성 → "지치고 흐려진 모습으로" 편집 파생.

### 2.3 프롬프트 템플릿 (자리표시)

```
[스타일 앵커 문장] 
[캐릭터 외형 묘사 — 팀 확정 설정 사용], 
knee-up standing pose, arms relaxed, facing slightly left, 
neutral expression, plain background, full body visible in frame, 
game visual novel character sprite
```
파생 시: 이미지 첨부 + `"Change only the facial expression to [happy/shy/...]. Keep pose, outfit, proportions, and framing identical."`

## 3. 배경 (담당: 미드저니)

### 3.1 필요 목록

| 파일명 (예) | 장면 | 우선순위 |
|---|---|---|
| `bg_hall_day` | 일상 — 심사장/복도 | 필수 |
| `bg_lounge_day` | 일상 — 챕터1 제2장소 | 필수 |
| `bg_street_evening` | 일상 — 챕터2 | 필수 |
| `bg_hall_dark` | 사건 발생 (기존 장소의 이변) | 필수 |
| `bg_hall_void` | 전투 (이계화 공간) | 필수 |
| `bg_title` | 타이틀 화면 | 필수 |
| 일상 배경 +1 | 챕터2 경로 분기용 | 컷 가능 |

- 같은 장소의 낮/저녁은 **새로 생성하지 말고 CSS 필터(색온도·명도)로 처리** — AI는 같은 구도를 재현하지 못한다. `bg_hall_dark`처럼 이변 연출도 가능하면 원본에 필터+오버레이로 우선 시도하고, 부족할 때만 별도 생성.

### 3.2 생성 요령

- `--ar 16:9` 필수, 프롬프트에 **"empty scene, no people, no characters"** 명시 (배경에 인물이 섞이면 스탠딩과 충돌)
- 첫 번째로 채택한 배경을 **스타일 레퍼런스로 재사용**(`--sref` 등 레퍼런스 기능)해 이후 배경의 색감·화풍을 통일
- 업스케일 후 1920×1080로 크롭·리사이즈 → webp 압축
- 원근이 과한 컷은 피한다 — 스탠딩 캐릭터를 올렸을 때 바닥 선이 어긋나 보인다. 아이레벨(눈높이) 구도 권장

## 4. UI (담당: 코드 생성 — Codex)

- **대화창·이름표·버튼·게이지는 이미지가 아니라 CSS로 만든다.** 해상도 대응이 쉽고 수정이 즉각이며, 100% AI 원칙(코드 생성)에도 부합한다.
- 이미지/SVG가 필요한 것만 최소로:

| 항목 | 방식 | 비고 |
|---|---|---|
| 마이크 상태 아이콘 3종 (대기/청취/처리) | SVG 코드 생성 | **가장 중요한 UI** — 청취 중은 애니메이션(맥동)으로 |
| 호감도·기세 게이지 | CSS (스킨 색만 교체해 공용) | 심사 노출용 — 음성이 수치를 움직이는 것을 보여준다 |
| 실시간 자막 영역 | CSS | 인식 중 텍스트 표시 (기획서 §3) |
| 클릭 폴백 버튼 3개 | CSS | |
| 장식 프레임 (선택) | GPT Image | 컷 가능 |

## 5. 오디오 (담당: Suno + 코드 생성)

### 5.1 BGM 목록 (Suno)

| 파일명 | 용도 | 길이 | 우선순위 |
|---|---|---|---|
| `bgm_daily` | 일상 파트 루프 | 60~90초 | 필수 |
| `bgm_battle` | 전투 루프 | 60~90초 | 필수 |
| `bgm_transform` | 변신 징글 | 10~20초 | 필수 |
| `bgm_crisis` | 사건 발생 | 30~60초 | 컷 가능 (battle 곡 앞부분 재활용 가능) |
| `bgm_ending` | 엔딩 | 60초 | 컷 가능 |

### 5.2 Suno 제작 요령

- 프롬프트에 **"instrumental"을 명시**해 가사를 방지한다 — 예외: **변신 징글은 짧은 가사(주문 콜)를 넣는 연출도 유효**하니 두 버전을 뽑아 비교
- 장르·BPM·분위기를 구체적으로 지정하고, 곡 간 통일감을 위해 같은 악기 편성 키워드를 재사용
- **루프 처리:** 생성곡의 인트로/아웃트로를 잘라 루프 구간을 만든다 — ffmpeg으로 트림 + `loudnorm` 볼륨 정규화 (Codex에게 명령어 생성 요청)
- 크로스페이드 전환은 엔진이 담당하므로 곡 자체의 페이드아웃은 불필요

### 5.3 SFX (코드 생성)

Suno는 단발 효과음에 부적합하므로 SFX는 **Web Audio 오실레이터 신스 코드로 생성**한다(Codex 담당, 파일 용량 0):
결정음(선택 확정) / 시전음(주문 성공) / 크리티컬음 / 타격·플래시음 / 인식 실패음 — 총 5종 내외.

## 6. 제작 순서와 검수

1. **스타일 앵커 확정** (샘플 2~3장 생성 → 팀 합의) — 모든 본생산의 전제
2. 주노 표정 5종 → 정렬 QA (오니언 스킨)
3. 배경 6종 (스타일 레퍼런스 연결)
4. 전투 세트 (망령 2상태, 마법소녀 뒷모습, 변신 컷 2)
5. BGM 3곡 + 루프 처리
6. 압축 → `public/assets/` 배치 → 게임 내 통합 확인 (기획서 M5)

**최종 검수 체크리스트**
- [ ] 파일명이 시나리오 JSON 참조와 100% 일치
- [ ] 주노 5종을 빠르게 전환해도 몸이 흔들리지 않음
- [ ] 스탠딩을 각 배경 위에 올렸을 때 발 위치·조명 방향이 어색하지 않음
- [ ] BGM 루프 경계에서 끊김이 들리지 않음
- [ ] 총 용량 30MB 이하, 첫 화면 로딩 3초 이내 (기본 에셋 프리로드 + 나머지 지연 로드)
