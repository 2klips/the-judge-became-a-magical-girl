# 음성 미연시(비주얼 노벨) 게임 로직 기획안 — 해커톤 예선용

> **결론: A안을 권고한다.** LLM 자유 대화 + 스탯 수렴 방식이 심사 주제("AI를 활용한 게임 제작")에 정면으로 부합하고, A안의 리스크(키 관리·지연·장애)는 설계로 전부 상쇄 가능한 반면 B안의 리스크(감정 오판)는 상쇄 수단이 없기 때문이다.

---

## 0. 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 아키텍처 | **A안** (LLM 자유 대화 + 호감도/감정 스탯 → 사전 정의 분기 수렴) |
| LLM | Gemini 2.5 Flash-Lite (JSON 강제 출력 `responseSchema` 사용) |
| API 키 처리 | **외부 프록시 (Cloudflare Workers 무료 티어)** — 3안 중 택1 결론 |
| 폴백 | 모든 노드에 클릭 선택지 + 키워드 로컬 판정 내장 → **LLM·네트워크 없이도 완주 가능** |
| STT | Web Speech API (`SpeechRecognition`, ko-KR), Push-to-Talk 방식 |

### B안을 기각하는 이유 (짧게)

1. **브라우저 STT는 운율을 주지 않는다.** B안이 성립하려면 `SpeechRecognition`과 별개로 `getUserMedia` + `AudioContext`로 원시 오디오를 병행 캡처해 피치(자기상관), RMS 성량, 발화속도를 직접 추출해야 한다. 구현 자체는 가능하지만 이중 오디오 파이프라인이 되고, 마이크 기종·시연장 소음·화자 개인차에 따라 추정치가 크게 흔들린다.
2. **오판이 곧 데모 실패다.** 프로소디 기반 감정 추정은 통제된 환경에서도 정확도가 낮고, 판정이 틀리면 플레이어(심사위원)가 "왜 이 분기로 갔는지"를 납득할 수 없다. 라벨 데이터 수집·튜닝을 할 시간도 없다.
3. **"AI 활용" 어필이 약하다.** STT는 브라우저 내장 기능이라 팀의 AI 활용으로 보이지 않고, 신호처리 휴리스틱은 심사 관점에서 AI가 아니다. A안의 실시간 생성 대화가 시연 임팩트에서 압도적으로 유리하다.

단, B안의 정신(로컬 판정)은 버리지 않는다 — **A안의 폴백 레이어(키워드 매칭)로 흡수**한다. 아래 대화 루프 참조.

## 1. API 키 결론: 외부 프록시 (Cloudflare Workers)

**택1 결론: 외부 프록시.** 이유:

- **클라이언트 노출 감수 → 기각.** GitHub Pages 무료 배포는 공개 레포가 전제다. 키를 JS 번들에 넣으면 봇 스크래핑 대상이 되고, GitHub 시크릿 스캐닝이 Google과 연동되어 있어 커밋된 키가 **자동 폐기·차단될 수 있다.** 심사 당일 키가 죽어 있는 최악의 시나리오가 현실적으로 발생한다.
- **사용자 키 입력 → 기각.** 링크 심사 위원은 API 키가 없다. 키 입력창을 보는 순간 플레이가 끝난다.
- **외부 프록시 → 채택.** Cloudflare Workers 무료 티어(일 10만 요청)에 30줄 내외의 중계 코드를 1회 배포한다. 키는 Workers 환경변수에만 존재한다. "자체 백엔드 서버 없음" 확정과의 정합성: 이것은 우리가 운영·유지보수하는 서버가 아니라 관리 대상이 없는 서버리스 엔드포인트이며, 갈림길 조건에서 외부 프록시가 선택지로 명시되어 있으므로 위배가 아니다. 코드는 AI가 생성한다(100% AI 제작 원칙 유지).

프록시에 넣을 최소 기능: ① 키 은닉(환경변수) ② Origin 화이트리스트(`*.github.io` 우리 도메인만) ③ 일일 호출 상한 ④ 4초 타임아웃. 예비 키 1개를 준비하고 **심사 직전 키 로테이션**을 체크리스트에 넣는다.

비용: Flash-Lite는 저가·저지연 라인이고 무료 티어가 존재한다. 데모 1회 호출량은 30~60콜 수준이라 비용은 사실상 0에 수렴할 것으로 보이나, **정확한 단가와 무료 한도는 제출 시점에 확인 필요.**

## 2. 상태 모델

| 상태값 | 형 / 범위 | 갱신 시점 | 용도 |
|---|---|---|---|
| `affinity` | int 0~100, 시작 50 | 매 턴 판정 후. 턴당 델타 **-3~+3 클램프** | 분기점·엔딩 판정의 주축 |
| `npcEmotion` | enum: `neutral / happy / shy / upset / surprised` | 매 캐릭터 응답마다 | 표정 에셋과 1:1 매핑 |
| `flags` | Set&lt;string&gt; | 의도(intent) 매칭 시에만 | 스토리 이벤트 기록, 엔딩 조건 |
| `nodeTurn` | int | 매 사이클 +1, 노드 이동 시 0 | 노드별 턴 상한 판정 |
| `totalTurn` | int | 매 사이클 +1 | 전역 상한(데모 시간) 판정 |
| `currentNodeId` / `history[]` | string / string[] | 분기 이동 시 | 진행 위치, 디버그 |
| `inputMode` | `voice` \| `click` | 실패 누적 시 전환 | 대체 입력 경로 |
| `sttFailCount` / `llmFailCount` | int | 실패 시 +1, 성공 시 0 | 폴백 트리거 |

**핵심 규칙: 상태는 오직 "판정 결과"로만 변한다.** LLM의 자유 텍스트가 임의로 플래그를 만들거나 호감도를 크게 흔들 수 없다. 플래그는 노드에 정의된 화이트리스트(`allowedFlags`) 안에서만 셋 가능하고, 호감도 델타는 클램프된다. 이것이 "LLM이 스토리를 폭주시키는 것"을 구조적으로 막는 장치다.

상태 스냅샷은 매 분기 이동 시 `localStorage`에 저장한다(새로고침 사고 복구용 — 시연 보험이지 세이브/로드 기능이 아님).

## 3. 대화 루프 (1 사이클)

```
[대기] → [① 음성 입력] → [② 1차 로컬 판정] → [③ 2차 LLM 판정] → [④ 연출] → [⑤ 상태 갱신] → [⑥ 분기 판정] → [대기 or 다음 노드]
```

**① 음성 입력 — Push-to-Talk.** 버튼(또는 스페이스바) 홀드 중에만 `SpeechRecognition` 가동, 손을 떼면 종료. 상시 청취는 시연장 소음이 그대로 입력되므로 금지. 결과: `transcript` + `confidence`. 빈 결과·저신뢰 → 캐릭터가 "미안, 잘 못 들었어" 재요청. **같은 턴에서 2회 실패하면 그 턴만 클릭 선택지를 노출**한다.

**② 1차 로컬 판정 (LLM 생략 경로).** 현재 노드 `intents`의 `keywords`와 transcript를 매칭한다(부분 일치 + 유의어). 명확히 매칭되면 해당 의도로 확정하고, LLM은 "의도 확정됨, 응답 문장만 생성"으로 역할이 축소되거나(온라인) 정의된 고정 응답을 재생한다(오프라인). 이 레이어 덕분에 **네트워크가 완전히 죽어도 게임이 완주된다.**

**③ 2차 LLM 판정 (미매칭 시).** 프록시 경유로 Flash-Lite 호출. 입력: 페르소나 시트 + 현재 노드의 `objective`/`llmContext` + 상태 요약(호감도, 플래그) + 최근 대화 2~3턴 + 플레이어 발화. 출력은 `responseSchema`로 **JSON 강제**:

```json
{ "reply": "캐릭터 대사", "intent": "invite_weekend | ... | freeform",
  "affinityDelta": -3~3, "emotion": "happy", "flags": ["asked_out"] }
```

`intent`는 노드에 정의된 목록 + `freeform`만 허용. 타임아웃 4초, 파싱 실패 시 1회 재시도, 그래도 실패면 노드의 `fallbackReplies` 중 하나 + 중립 판정(델타 0)으로 턴을 넘긴다.

**④ 연출.** 표정 스왑 → 타이핑 효과로 대사 출력. (선택: `speechSynthesis`로 TTS — 브라우저 내장·무료, 스트레치 항목)

**⑤ 상태 갱신.** 델타 적용(클램프), 화이트리스트 검증 후 플래그 셋, `nodeTurn`/`totalTurn` +1.

**⑥ 분기 판정 — 우선순위 순서대로:**
1. 매칭된 intent에 `next`가 있으면 → 즉시 해당 노드로 이동
2. `nodeTurn ≥ maxTurns` → 노드의 `exitOnMaxTurns` 조건표(호감도 구간)로 **강제 이동**
3. 둘 다 아니면 → 같은 노드에서 다음 턴 루프

## 4. 분기 구조

```
프롤로그(고정 연출, 입력 없음)
  → 챕터1 (노드 2개: 자유 대화로 호감도 적립)
  → [분기점①] 호감도 3구간 분기 (≥60 / 40~59 / <40)
  → 챕터2 (경로별 노드 1~2개)
  → [분기점②] 의도 선택 분기 — 핵심 플래그 획득 여부가 갈림
  → 챕터3 (수렴 노드 1개: 모든 경로가 합류)
  → [최종 분기] 호감도 × 플래그 매트릭스
  → 엔딩
```

- **분기점 3개** (중간 2 + 최종 1), **대화 노드 8~10개 + 엔딩 노드 4개**
- 중간 노드들은 분기하지 않고 호감도·플래그 적립 역할만 한다 (분기는 챕터 경계에서만 — 작가 규칙 §7 참조)

**엔딩 4종과 도달 조건:**

| 엔딩 | 조건 | 비고 |
|---|---|---|
| GOOD | `affinity ≥ 70` AND `flag:promise` | |
| NORMAL | `affinity ≥ 40` | |
| BAD | `affinity < 40` | |
| HIDDEN | 특정 플래그 2개 조합 (호감도 무관) | **컷 1순위** — 여유 있을 때만 |

**시간 계산:** 1턴 ≈ 발화 3~5초 + STT/LLM 1~3초 + 대사 읽기 10~15초 ≈ 20~25초. 노드 10개 × 평균 4턴 = 약 40턴 ≈ **14~17분.** 노드당 `maxTurns`를 config에서 4(짧은 시연) ↔ 6(긴 시연)으로 한 줄 전환하면 10~30분 범위를 모두 커버한다.

## 5. 대화 수렴 규칙 (늘어짐 방지)

1. **노드 턴 상한 4~6.** 도달 시 무조건 `exitOnMaxTurns`로 이동한다. 강제 전환은 시스템 메시지가 아니라 스토리상 자연스러운 대사로 포장한다("어, 벌써 시간이 이렇게 됐네 — 저기…").
2. **캐릭터가 수렴을 주도한다.** LLM 시스템 프롬프트에 노드의 `objective`("N턴 안에 플레이어가 X에 답하도록 유도하라")를 넣어, 캐릭터가 능동적으로 핵심 질문을 던지게 한다. 수렴은 플레이어 책임이 아니라 캐릭터 책임이다.
3. **freeform 3연속 시 유도 질문 강제 삽입.** 잡담이 이어지면 다음 응답에 노드의 핵심 질문을 반드시 포함하도록 지시를 추가한다.
4. **전역 상한 `totalTurn = 45`.** 도달 시 현재 호감도로 최종 분기에 점프한다(데모 오버런 방지 최후 보루).
5. **판정 실패 처리.** STT 같은 턴 2회 실패 → 그 턴 클릭 모드. 세션 누적 5회 실패 → `inputMode`를 `click`으로 영구 전환(토글로 복귀 가능). LLM 3연속 실패 → "로컬 모드"(키워드 판정 + 정의된 고정 응답만)로 강등하되 게임은 계속된다.

## 6. 데이터 포맷

파일 구성: `scenario.json`(노드 배열) + `characters.json`(페르소나·표정 목록) + `config.json`(임계치·턴 상한·프록시 URL). 노드 스키마 예시 1개 (내용은 더미):

```json
{
  "nodeId": "ch1_cafe_talk",
  "scene": { "bg": "bg_cafe_day", "bgm": "bgm_calm" },
  "npc": { "id": "npcA", "startEmotion": "neutral" },
  "objective": "플레이어의 취향을 파악하고, 주말 약속 화제로 유도한다",
  "opening": "여기 자주 와? 나는 오늘 처음 와 봤어.",
  "llmContext": "방과 후 카페. NPC는 플레이어와 아직 서먹하며 공통 관심사를 찾고 싶어한다.",
  "maxTurns": 5,
  "intents": [
    {
      "id": "invite_weekend",
      "clickLabel": "주말에 같이 나가자고 한다",
      "examples": ["주말에 시간 있어?", "토요일에 같이 갈래?"],
      "keywords": ["주말", "토요일", "일요일", "같이 가", "갈래"],
      "affinityDelta": 3,
      "setFlags": ["asked_out"],
      "npcEmotion": "shy",
      "next": "ch2_promise"
    },
    {
      "id": "ask_hobby",
      "clickLabel": "취미를 물어본다",
      "examples": ["취미가 뭐야?", "요즘 뭐에 빠져 있어?"],
      "keywords": ["취미", "좋아해", "관심"],
      "affinityDelta": 1,
      "setFlags": [],
      "npcEmotion": "happy",
      "next": null
    },
    {
      "id": "tease",
      "clickLabel": "장난스럽게 놀린다",
      "examples": ["카페를 처음 와 봤다고?"],
      "keywords": ["처음이야", "촌스럽"],
      "affinityDelta": -2,
      "setFlags": [],
      "npcEmotion": "upset",
      "next": null
    }
  ],
  "allowedFlags": ["asked_out"],
  "fallbackReplies": ["미안, 잘 못 들었어. 다시 말해 줄래?", "응? 방금 뭐라고 했어?"],
  "exitOnMaxTurns": [
    { "if": "affinity >= 60", "next": "ch2_promise" },
    { "if": "affinity >= 40", "next": "ch2_street" },
    { "default": "ch2_awkward" }
  ]
}
```

- `next: null` = 같은 노드에서 대화 계속 (호감도 적립용 의도)
- `clickLabel`은 **모든 의도에 필수** — 클릭 폴백 모드의 선택지가 된다
- 엔딩 노드는 `intents` 없이 `endingText` + `endingImage`만 갖는 단순 구조

## 7. 시나리오 작가 가이드 (A안 기준)

작가의 작성 단위는 **"노드"**다. 모든 발화 경우의 수를 쓰는 게 아니라, 노드마다 아래만 채운다:

**작가가 쓰는 것**

| 항목 | 분량 | 설명 |
|---|---|---|
| 페르소나 시트 (게임 전체 1장) | 반 페이지 | 말투·성격·금기어·1인칭/호칭·**예시 대사 5개** (LLM 말투 학습용) |
| 노드별: 장면·목적 | 1문장 | "이 노드에서 플레이어가 무엇을 하게 만들 것인가" — LLM이 수렴을 주도하는 근거 |
| 노드별: 오프닝 대사 | 1~2줄 | 노드 진입 시 캐릭터의 첫 마디 (고정 텍스트) |
| 노드별: 의도 3개 | 각 3~4줄 | 라벨 + 예시 발화 2개 + **키워드 5개 내외** + 호감 델타 + 플래그 + 다음 노드 |
| 노드별: 탈출표 | 2~3줄 | 턴 상한 도달 시 호감도 구간별 행선지 |
| 노드별: 폴백 대사 2~3개 | 각 1줄 | 못 알아들었을 때 캐릭터가 하는 말 |
| 엔딩 4개 본문 | 각 반 페이지 | 고정 텍스트 |

**작가가 쓰지 않는 것:** 자유 대화 구간의 개별 대사(LLM 몫), 플레이어 발화의 모든 변형.

**작가 규칙 3가지**

1. **선택지는 문장이 아니라 "의도"로 정의한다.** 음성 입력은 표현이 무한하므로 "주말에 같이 갈래?"라는 정답 문장이 아니라 "주말 약속을 제안하는 의도"를 키워드·예시와 함께 정의한다.
2. **분기는 챕터 끝에서만.** 중간 노드는 호감도·플래그 적립 역할만 한다. 분기점이 많아지면 노드 수가 지수적으로 늘어 예선 분량을 초과한다.
3. **모든 노드에 클릭 라벨 필수.** 음성이 죽었을 때 그 라벨이 그대로 선택지 버튼이 된다.

**분기점 작성 예시 (더미):**

> **분기점① — 챕터1 종료 시**
> - 호감도 ≥ 60: `ch2_promise` (약속 성사 루트) — 캐릭터가 먼저 설레는 기색
> - 40~59: `ch2_street` (애매한 동행 루트) — 우연을 가장한 재회로 이어짐
> - < 40: `ch2_awkward` (서먹 루트) — BAD 엔딩 압박, 만회 기회 1회 제공

## 8. 화면 구성 및 Asset 양식 (100% AI 생성 전제)

### 배경
- 장면당 1장, **1920×1080, webp**, 총 **6~7장** (노드 수 기준)
- 같은 장소의 낮/저녁 변형은 이미지를 새로 만들지 말고 **CSS 필터(색온도·명도)로 처리** — AI 생성 시 동일 구도 재현이 어렵기 때문

### 캐릭터 (예선 범위: 1명)
- **포즈는 1개 고정, 표정만 5종 교체**: `neutral / happy / shy / upset / surprised` — §2의 `npcEmotion` enum과 1:1
- 규격: 니샷(무릎 위) 스탠딩, **투명 배경 PNG, 동일 캔버스(예: 1200×2000)**, 모든 표정 파일에서 몸 위치가 픽셀 단위로 동일해야 표정 전환 시 캐릭터가 "튀지" 않는다
- **AI 생성 워크플로 (일관성 확보의 핵심):** ① 베이스 1장 생성 → ② **얼굴 영역만 인페인팅**으로 표정 5종 파생(몸은 그대로) → ③ 배경 제거 → ④ 동일 캔버스·동일 좌표에 배치. 표정마다 전신을 새로 생성하면 반드시 실패한다.
- 추가 포즈(클라이맥스용 1개)는 스트레치 — 없어도 성립

### UI 에셋
- 대화창 + 이름표 (9-slice 가능한 단순 프레임)
- **마이크 상태 표시 3종: 대기 / 청취 중 / 처리 중** — 음성 게임에서 사실상 가장 중요한 UI. 심사위원이 "지금 말해도 되는지"를 이것으로 판단한다
- **호감도 게이지 (노출 권장)** — 숨기는 게 미연시 관례지만, 심사에서는 "음성이 스탯을 움직인다"는 메커니즘을 눈으로 보여주는 것이 유리하다
- 클릭 선택지 버튼 3개 (폴백 모드용)
- 타이틀 화면 1장, 엔딩 카드는 배경 이미지 + 텍스트 오버레이로 대체 (별도 일러스트 제작 컷)

### 오디오
- BGM 2곡 루프, SFX 3~4개 (전환음·판정음) — 전부 컷 가능
- TTS는 브라우저 내장 `speechSynthesis` (한국어 음성 품질은 OS별 편차 큼 — 시연 기기에서 확인 필요)

### 네이밍 규칙
`bg_{장소}_{시간}.webp` / `char_{id}_{emotion}.png` / `ui_{이름}.png` / `bgm_{이름}.mp3` — 시나리오 JSON이 이 이름을 직접 참조한다.

## 9. 최소 기능 범위 (MVP 경계)

**예선 제출에 반드시 있어야 하는 것**

- 노드 엔진 + JSON 시나리오 로더
- Push-to-Talk 음성 입력 + 로컬 키워드 판정 + LLM 판정(JSON 강제)
- **클릭 폴백(전 노드) + 오프라인 로컬 모드** — 시연 보험, 절대 컷 불가
- 호감도·플래그·턴 상태 관리, 분기점 3개, 엔딩 3종(GOOD/NORMAL/BAD)
- 표정 5종 스왑, 배경 전환, 마이크 상태 표시, 타이틀/엔딩 화면
- Workers 프록시, Chrome 기준 동작
- **완주 시연 영상 사전 녹화** (심사 형태에 영상이 포함되므로 제출물이자 보험)

**잘라내는 것 (우선순위 순)**

HIDDEN 엔딩 → TTS → 추가 포즈 → BGM 2곡 이상·SFX → 세이브/로드 UI(자동 복구 스냅샷만 유지) → 대화 로그·스킵 기능 → 설정 화면 → 모바일/사파리 대응 → 캐릭터 2명 이상 → 갤러리

## 10. 리스크와 대응

| 리스크 | 발생 시점 | 대응 |
|---|---|---|
| 마이크 권한 거부 | 시연 시작 | 타이틀 화면에서 권한 선요청. 거부 시 자동으로 클릭 모드 안내 문구 + 전환 |
| 시연장 소음·오인식 | 현장 시연 | Push-to-Talk(상시 청취 금지), confidence 임계치, **지향성 유선 마이크 지참**, 현장 리허설 1회 |
| 브라우저 호환 | 링크 심사 | `SpeechRecognition`은 사실상 Chromium 계열 전용(Firefox 미지원, iOS Safari 동작 확인 필요). 제출 안내문에 "Chrome 권장" 명시 + 기능 감지 실패 시 자동 클릭 모드 |
| 네트워크 지연 | 매 턴 | LLM 4초 타임아웃 → 폴백 대사 + 중립 판정. Chrome STT는 서버 전송 방식이라 **완전 오프라인이면 STT도 죽는다** → 클릭 + 로컬 판정 모드로 강등, 완주는 보장 |
| API 키 유출·쿼터 소진 | 심사 기간 | Workers 프록시(키 은닉·Origin 제한·일일 상한), 예비 키 1개, 심사 직전 로테이션 |
| LLM 이탈·프롬프트 인젝션 | 자유 대화 | `responseSchema` JSON 강제 + intent 화이트리스트(분기는 인젝션의 영향을 받지 않음) + 시스템 프롬프트 가드 + `maxOutputTokens` 제한 |
| 총체적 실패 | 심사 당일 | 사전 녹화한 완주 영상 제출 (심사 형태에 영상 포함) |

**확인 필요 항목 (단정하지 않은 것들):** Gemini 2.5 Flash-Lite의 현재 단가·무료 티어 한도 / iOS Safari의 `webkitSpeechRecognition` 실동작 / ko-KR 인식 정확도 실기기 실측 / `SpeechRecognition` 연속 재시작(턴마다 start/stop 반복) 안정성.
