# 테스트일지 기반 시스템 개선 설계

## 1. 상태와 목적

- 상태: `[확정]`
- 승인일: 2026-08-13
- 대상: 데스크톱 16:9 본편 시연
- 기준 해상도: 1280×720, 1920×1080
- 모바일 검수: 이번 범위에서 제외
- 목표: 약 5분 전체 플레이에서 UI, 음성, BGM, 장면 전환, 전투, 엔딩이 한 흐름으로 보이게 한다.
- 복구 목표: 음성·네트워크 실패가 발생해도 내부 오류 문구를 노출하지 않고 같은 턴 재시도 또는 클릭 입력으로 자연스럽게 완주한다.

사용자가 제공한 테스트일지 15개 항목과 스크린샷 10장을 근거로 한다. 개별 화면에 CSS를 덧붙이는 방식 대신 공통 계약을 먼저 고쳐 같은 원인의 문제를 함께 해결한다.

## 2. 승인된 제품 결정

1. 메인화면은 왼쪽 무박스 한 줄 제목, 오른쪽 반투명 마이크 카드, 카드 오른쪽 하단 시작 버튼으로 구성한다.
2. 제목·본문·보조 문구는 저장소에서 직접 제공하는 `Pretendard Variable` 한 가족으로 통일하고 굵기·크기로 계층을 만든다. 시스템 fallback은 `Noto Sans KR`, `Apple SD Gothic Neo`, `system-ui`, `sans-serif` 순서다.
3. 신규 사용자의 BGM 기본 볼륨은 20%로 한다. 기존 사용자의 유효한 저장 볼륨·음소거 설정은 보존한다.
4. 메인화면에서 BGM 자동재생을 강제하지 않는다. 최초 마이크 연결 또는 시작 입력에서 오디오를 활성화하고 장면 BGM을 자연스럽게 시작한다.
5. 의미가 다른 고정 빨간 마이크 선은 제거한다. 입력 레벨, 적정 구간, 과입력 상태는 실제 판정 계약과 같은 값으로 표시한다.
6. 음성 입력 첫 실패는 같은 턴에서 한 번 재시도한다. 두 번째 실패 때만 현재 턴을 클릭 입력으로 전환한다. 실패한 턴이 누적 기준에 도달할 때만 전체 입력 모드를 클릭으로 전환한다.
7. `Failed to fetch`, HTML 응답, upstream 오류 원문은 production UI에 표시하지 않는다. 사용자 안내는 분류된 한국어 문구만 사용한다.
8. 변신 컷은 `cast 전면 컷 → crossfade → complete 전면 컷 → 결과 카드` 순서로 한 장씩 표시한다. 두 컷 동시 카드, 컷 테두리, 중복 도윤 스프라이트는 제거한다.
9. 전투 기본 구도는 도윤·주노 왼쪽, 회색 망령 오른쪽이다. 도윤과 망령은 서로 화면 안쪽을 바라본다.
10. 전투 p1·p2는 시간정지된 동료가 보이는 같은 사무실 공간을 유지한다. 회색 침식은 배경 교체가 아니라 단계적 연출로 강화한다. p3 공간 전환은 서사적으로 명확하게 보이게 한다.
11. 전투 종료는 정화, 망령 외피 해체, 짧은 암전 설명, 수렴 장면 순서로 진행한다.
12. 필수 신규 이미지 생성은 0장이다. 기존 에셋·배치·CSS 검증 뒤 부족할 때만 주노 자기소개 포즈 1장을 별도 승인 대상으로 제안한다.

## 3. 공통 원인

### 3.1 누적된 화면 스타일

`src/styles.css`에는 마일스톤별 UI 규칙이 여러 차례 누적되어 동일 selector가 반복 정의된다. 장면마다 다른 CSS를 추가하면 수정 순서에 따라 글꼴, 패널 투명도, 위치가 다시 달라진다.

해결 원칙:

- 디자인 토큰과 최종 selector 소유권을 한 곳으로 통합한다.
- 과거 UI pass를 정리하고 새 override 층을 추가하지 않는다.
- 화면 종류가 달라도 같은 `SceneFrame` 안전영역을 사용한다.

### 3.2 독립된 절대좌표

캐릭터, 대화창, 조작 dock, 전투 HUD, BGM 설정이 각각 화면 가장자리를 기준으로 배치된다. 서로의 영역을 알지 못해 작은 높이에서도 겹친다.

해결 원칙:

- 공통 슬롯을 `hud / stage / dialogue / actions / audio`로 나눈다.
- 각 슬롯은 단일 안전영역 변수와 z-index 토큰을 사용한다.
- 주요 캐릭터 얼굴·손·지팡이·망령 실루엣을 가리지 않는 장면별 anchor만 별도로 둔다.

### 3.3 기능 계약과 화면 표현의 불일치

- BGM 기본값은 현재 62%다.
- 마이크 빨간 선은 실제 setup·battle 판정과 같은 기준이 아니다.
- production 음성 경로는 첫 실패를 바로 클릭으로 강등하며 내부 오류 원문을 노출할 수 있다.
- 화자 강조 코드는 있지만 전투 결과에서도 활성 화자가 망령으로 고정된다.

해결 원칙:

- 수치와 상태는 도메인 판정 결과에서만 가져온다.
- UI는 raw 오류가 아니라 제한된 presentation 상태만 받는다.
- 장면별 화자와 행동 주체를 beat 단위로 명시한다.

### 3.4 동시 노출 중심 연출

인물, 적, 대사, 선택지, 컷, 결과 카드가 한 번에 나타나 주요 사건이 묻힌다.

해결 원칙:

- 순차 연출 primitive를 재사용한다.
- 한 beat에는 주요 사건 하나만 둔다.
- 모션 감소 설정에서는 같은 순서를 즉시 상태 변화로 제공한다.

## 4. 설계 구조

### 4.1 디자인 토큰

최종 토큰은 다음 책임만 가진다.

- `--font-ui`: 제목, 본문, 버튼, HUD의 한글 sans 글꼴
- `--type-title`, `--type-body`, `--type-meta`: 크기와 행간
- `--surface-dialogue`, `--surface-actions`, `--surface-modal`: 용도별 투명도
- `--safe-top`, `--safe-bottom`, `--safe-inline`: 공통 안전영역
- `--z-background`, `--z-character`, `--z-dialogue`, `--z-actions`, `--z-hud`, `--z-audio`: 쌓임 순서
- `--speaker-juno`, `--speaker-doyun`, `--speaker-wraith`, `--speaker-narration`: 화자 accent

화자별 차이는 패널 전체 색보다 테두리, 이름표, 작은 광원으로 표현한다. 본문 대비는 배경 이미지와 관계없이 읽을 수 있게 국소 scrim으로 확보한다.

### 4.2 SceneFrame

`GameView`의 화면 생성은 공통 `SceneFrame` 슬롯을 사용한다.

- `hud`: 단계, 기세, 진행 상태
- `stage`: 배경, 캐릭터, 효과
- `dialogue`: 화자명, 대사, 내레이션
- `actions`: 선택지, PTT, 진행 버튼
- `audio`: BGM 설정

`renderLine`, `renderDialogue`, `renderTransformationResult`, `renderBattle`, `renderEnding`은 슬롯을 조합하되 직접 화면 가장자리에 좌표를 중복 선언하지 않는다.

### 4.3 순차 연출 primitive

공통 primitive는 다음 여섯 개다.

1. `scene beat`: 대사·컷·조작을 순서대로 연다.
2. `active speaker focus`: 활성 화자 1명만 밝게 하고 나머지는 낮춘다.
3. `reaction mark`: 기존 스프라이트 위에 `?` 또는 `!` 반응을 짧게 표시한다.
4. `entrance/exit`: 첫 등장과 퇴장을 일반 표정 교체보다 길게 보여 준다.
5. `battle action`: 준비, 공격, 피격, 회복 상태를 순차 표시한다.
6. `safe-zone composition`: 인물·대사·조작·HUD가 서로 침범하지 않게 배치한다.

이 primitive는 전역 이벤트 버스 없이 기존 직렬 FSM과 `GameView` 내부 presentation 상태로 구현한다.

## 5. 화면별 설계

### 5.1 메인화면

- 왼쪽: 배경의 빈 하늘 영역을 이용한 한 줄 제목과 짧은 부제
- 오른쪽: 반투명 마이크 카드
- 카드 내용: `마이크 테스트`, 입력 장치, 실제 판정과 일치하는 level 상태, 테스트 문장, 동적 안내
- 삭제: “연결되어야 플레이”, “마이크 준비”, “마이크를 연결하고”의 중복 설명
- 시작·이어하기: 카드 오른쪽 하단에 일관된 CTA
- BGM 패널: 제목·마이크 카드와 겹치지 않는 고정 audio slot

### 5.2 시작 훅과 주노 소개

- 시작 독백: `다음 게임은 뭐지…… 제목이 ‘심사역은 마법소녀가 되었다’……?`
- 도윤에게 기존 놀람 스프라이트와 `?`를 사용한다.
- 주노 실제 등장 때 `!`, 등장 SFX, first-entry를 적용한다.
- `엥? 내가?`는 기존 관련 intent의 examples·keywords를 보강해 같은 분기로 수렴한다.
- `마법소녀는 뭐 하는 거야?`는 기존 `ask_identity` intent에 수렴한다.
- 주노 자기소개는 기존 happy 에셋과 active focus를 먼저 사용한다. 새 포즈는 1차 QA 뒤 부족할 때만 검토한다.

### 5.3 회색 망령 등장

- daily BGM을 낮춘 뒤 crisis BGM으로 짧게 전환한다.
- 모니터·공간 변화, 안개, 회색 망령 단독 등장 순으로 전조를 만든다.
- 망령 대사 1 beat 뒤 주노 설명과 3인 구도로 넘어간다.
- N3 첫 진입에서만 entrance를 재생하고 같은 노드 rerender에서는 반복하지 않는다.

### 5.4 사원증과 변신

- 사원증 부유 첫 beat: `doyun.normal_startled`
- 망령 압박·주문 준비: 기존 shy 계열로 전환
- 변신 결과: 한 시점에 전면 컷 1장만 표시
- 컷 위 중복 캐릭터와 흰 테두리 카드 제거
- 결과 카드와 CTA는 컷 완료 뒤 표시

### 5.5 전투

- 도윤·주노 왼쪽, 회색 망령 오른쪽
- 도윤과 망령은 안쪽을 바라보게 기존 에셋의 배치·반전 가능성을 우선 사용
- 주노는 도윤 지팡이와 분리된 anchor 사용
- prompt: 준비 포즈
- 선택 후: p1 defend, p2 attack, p3 finish 포즈
- 행동 beat: 행동 주체 focus → 준비/공격 → 피격+SFX → 대사 → 결과/다음 행동
- p1·p2: 시간정지 동료가 보이는 배경 유지
- p3: 기록 공간 전환을 별도 beat로 표시
- BGM panel과 battle HUD 사이 최소 16px
- dialogue와 action dock 사이 최소 16px
- 배경의 파란 장벽은 재사용 가능한 기존 배경으로 먼저 교체 검증하고, 해결되지 않을 때만 원본 배경 수정안을 별도 승인받는다.

### 5.6 전투 종료와 엔딩

- 마지막 공격·판정 뒤 정화 효과
- 망령 외피가 풀리고 작은 빛이 남는 설명
- 짧은 암전 내레이션
- 수렴 장면 진입
- 엔딩은 한 beat에 카드 하나만 표시하고 캐릭터 얼굴·몸통과 겹치지 않는 safe zone을 사용한다.

## 6. 오디오·음성 데이터 흐름

### 6.1 BGM

1. 설정 로더가 유효한 저장값을 읽는다.
2. 저장값이 없거나 손상됐으면 20%를 사용한다.
3. 사용자의 첫 오디오 관련 입력에서 Audio 재생 권한을 확보한다.
4. 장면 변경은 `daily / crisis / transform / battle / ending` cue를 요청한다.
5. 서로 BPM이 다른 곡은 긴 overlap보다 짧은 fade-through-silence를 사용한다.
6. 빠른 장면 변경에서도 audible channel은 하나만 남긴다.

각 loop 음원은 코드 수정과 별개로 bar 경계, head/tail seam, LUFS, peak를 확인하고 헤드폰으로 3회 반복 검수한다.

### 6.2 음성 오류

음성 실패는 `recording / permission / network / timeout / HTTP / schema / no-speech`로 구분한다. presentation 계층에는 허용된 상태와 한국어 안내만 전달한다.

1. 첫 실패: 같은 턴 음성 재시도
2. 두 번째 실패: 현재 턴 클릭 입력
3. 실패한 턴 누적: 기존 계약 기준에 도달하면 전체 클릭 모드
4. 성공: 해당 턴 실패 상태를 종료하고 정상 판정

production DOM에는 `Failed to fetch`, HTML, API 원문, 모델명, provider명을 표시하지 않는다.

## 8. 토큰·시간 절감 원칙

1. 15개 이슈를 6개 공통 계약으로 관리한다.
2. 공통 primitive를 먼저 테스트하고 장면에서는 selector·cue만 연결한다.
3. 화면별 새 CSS override를 추가하지 않는다.
4. 신규 이미지 생성 전 기존 에셋, crop, anchor, 반전, 순차 표시를 먼저 검증한다.
5. 각 묶음은 `RED → 최소 구현 → targeted 검증 → 데스크톱 preview → 전체 검증 → 커밋`으로 닫는다.
6. 같은 실패 로그와 스크린샷을 여러 에이전트에 반복 전달하지 않고 묶음별 계약과 수용 기준만 전달한다.
7. 문서 사실은 기존 SSOT 역할에 맞게 분리한다. 구현 결과는 `IMPLEMENTATION_LOG.md`, 결정은 `DECISIONS.md`, 사용자 학습 설명은 `LEARNING_LOG.md`에 기록한다.

- 메인부터 GOOD/NORMAL/BAD 엔딩까지 전체 5분 플레이
- 실제 Chrome, 실제 마이크, 실행 중인 Worker
- `엥? 내가?`, `마법소녀는 뭐 하는 거야?` 발화 수렴
- 망령 단독 등장 뒤 3인 구도
- 변신 한 컷씩 표시, 흰 테두리·중복 스프라이트 0
- 도윤·주노 왼쪽, 망령 오른쪽 대치와 지팡이 겹침 0
- p1·p2 시간정지 직원 유지
- BGM/HUD, dialogue/actions, 엔딩 카드/캐릭터 겹침 0
- 각 BGM 3회 loop에서 클릭·무음·박자 점프 0
- console warn/error와 화면 raw 오류 문구 0

## 10. 범위 제외와 승인 게이트

- 모바일 레이아웃 개선
- 신규 UI 프레임워크·전역 이벤트 버스 도입
- 시나리오 스키마·에셋 ID의 전면 변경
- 자유 대화 구조·엔딩 조건·3페이즈 배틀 규칙 변경
- 신규 이미지·BGM·SFX의 자동 채택
- 원격 push, main merge, 공개 배포

주노 신규 포즈, 배경 원본 수정, 새 타격음 채택, BGM 원본 재편집은 비교안과 권리·품질 근거를 먼저 보고한 뒤 사용자 승인을 받는다.

## 11. 완료 기준

이 설계의 구현은 다음 조건을 모두 만족할 때 완료다.

1. 테스트일지의 15개 항목이 공통 계약 또는 장면 수용 기준으로 추적된다.
2. 기능 실패가 production UI에 내부 오류 원문으로 노출되지 않는다.
3. 데스크톱 16:9 전체 플레이에서 주요 UI 겹침이 없다.
4. 장면마다 한 번에 하나의 주요 사건이 읽힌다.
5. 신규 필수 이미지 없이 기존 에셋으로 1차 구현을 끝낸다.
6. 자동 검증과 실제 마이크·Worker·헤드폰 수동 검증을 모두 통과한다.
7. 변경 범위, 검증 결과, 화면 영향, 비용 절감 근거, 커밋 SHA가 역할에 맞는 문서에 기록된다.
