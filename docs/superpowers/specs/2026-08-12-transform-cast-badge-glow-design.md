# `transform.cast` 사원증 인증광 보정 설계

- 작성일: 2026-08-12
- 대상 논리 ID: `transform.cast`
- 대상 파일: `assets/source/p0-required-images/delivery/cut_transform_01.webp`, `assets/runtime/cut/cut_transform_01.webp`
- 기준 커밋: `f55e5cc812f873de2a0058461e166d21f99caf40`
- 화면 범위: 데스크톱 16:9 전용. 모바일은 사용자 방침에 따라 제외한다.

## 1. 목적

현재 영창 컷은 도윤이 사원증을 직접 내밀고 말하며 주노가 함께 기도하는 동작을 명확히 보여 준다. 다만 사원증의 흰 카드 면이 주변 마법진과 별빛에 비해 정적으로 보여, 사원증이 변신을 시작하는 인증 매개체라는 인과가 약하다.

사원증 안쪽에서 인증광이 켜지는 장면으로 보정해 `사원증 제시 → 마법 인증 발동 → 변신 완료`의 흐름을 한눈에 읽히게 한다.

## 2. 확정 방향

사용자가 비교 시안의 **A2 균형형 인증 발동**을 선택했다.

- 흰 카드 면 안쪽에서 청백색 빛이 발생한다.
- 빛은 기존 파란 플라스틱 테두리를 지우지 않고 안쪽에서 바깥으로 번진다.
- 기존 파란 테두리, 클립, 파란 목걸이 끈은 형태와 색을 유지한다.
- 테두리 밖에는 경계가 없는 부드러운 청색 후광만 둔다.
- 카드 주변에 작은 금색 입자 3~5개를 둔다.
- 별도의 단단한 흰색 사각 발광 테두리, 추가 프레임, 두 번째 사원증은 만들지 않는다.

## 3. 시각 강도

발광은 사원증을 장면의 시작점으로 만들되 카드와 손의 구조를 보존하는 중간 강도다.

- 카드 면 중앙은 밝은 청백색이지만 완전한 흰색 덩어리로 날리지 않는다.
- 카드 면과 파란 테두리의 경계가 계속 식별돼야 한다.
- 후광은 사원증 외곽과 잡고 있는 손가락에 약하게 반사되며 도윤 얼굴까지 번지지 않는다.
- 금색 입자는 기존 장면의 금색 별빛과 이어지되, 사원증 형태를 가리지 않는다.
- 강한 광선, 렌즈 플레어, 화면 전체 백색 섬광, 변신 완료처럼 보이는 폭발광은 제외한다.

## 4. 보존 불변식

이미지 편집은 사원증 발광만 대상으로 한다. 다음 요소는 현재 최종본과 동일하게 유지한다.

- 평상복 도윤 한 명
- 도윤의 얼굴, 정체성, 머리, 진지하고 약간 부끄러운 표정과 중간 크기의 발화 입
- 사원증을 전경으로 내미는 팔·손·손가락의 자연스러운 연결과 원근
- 무문자 사원증 정확히 한 개
- 눈을 감고 세운 별 지팡이 주위로 두 날개를 모은 주노 한 명
- 청색·금색 야간 사무실, 원형 마법진, 리본형 마력 궤적, 전체 16:9 구도
- 읽을 수 있는 글자, 개인정보, 사진, 로고, UI, 워터마크 없음

도윤이나 주노의 위치·비율·포즈를 다시 구성하거나 배경·마법진을 교체하지 않는다.

## 5. 제작 방식

현재 채택본 `cut_transform_01.webp`를 편집 대상으로 사용한다. Codex 내장 이미지 편집 도구로 사원증 영역만 정밀 보정하고, 후보 검수 후 프로젝트 규격으로 정규화한다.

1. 현재 최종본을 입력 이미지로 사용한다.
2. A2 발광과 보존 불변식을 편집 프롬프트에 함께 명시한다.
3. 인물·손·사원증 개수·주노 자세·배경 드리프트를 먼저 검수한다.
4. 발광이 약하거나 단단한 추가 테두리가 생겼을 때만 한 차례 표적 보정을 허용한다.
5. 최종본을 1920×1080 WebP, 700KB 이하로 정규화한다.
6. source/runtime에 동일 바이트를 채택한다.

비교 화면의 CSS 발광은 강도 선택용 시뮬레이션이며 최종 픽셀 결과의 형태 기준이 아니다.

## 6. 검증

### 자동 검증

- source/runtime 파일 존재 및 동일 바이트
- 1920×1080 WebP, 700KB 이하
- 교체 전 SHA-256을 거부하는 회귀 guard
- 기존 전체 `npm run check`, `npm test`, `npm run build`

### 데스크톱 화면 검증

- `n5-incantation`에서 평상복 선행 상태 유지
- `n5-transformation`의 `cast`에서 사원증 내부 발광이 인증 시작점으로 읽힘
- 기존 파란 테두리·클립·손가락이 식별됨
- 별도의 단단한 바깥 사각 테두리와 추가 사원증이 없음
- 도윤 발화 입과 주노 기도 자세가 그대로 읽힘
- `cast → complete` 순서와 후속 마법 복장 완료 컷 유지
- 1280×720에서 가로 overflow 0, console error 0

모바일 crop 및 모바일 브라우저 QA는 범위 밖이다.

## 7. 코드·문서 범위

게임 production 코드, catalog, 시나리오 JSON, CSS, 논리 ID, 장면 순서는 수정하지 않는다. 자산 두 파일, 자산 회귀 테스트, 관련 자산·구현·학습 기록만 갱신한다.

기존 문서의 SSOT 우선순위와 역할은 바꾸지 않는다.

- `AI_PRODUCTION_LOG.md`: 생성·선택·사람 승인 상태
- `IMPLEMENTATION_LOG.md`: 파일 교체·자동/화면 검증 증거
- `LEARNING_LOG.md`: 초보자용 발광 계층과 시각적 인과 설명
- manifest·scene mapping·provenance: 현재 자산 사실과 장면 계약

## 8. 승인 상태

자동 계약과 데스크톱 화면 검증을 통과하면 `ready`로 기록한다. 사람 미술 품질, 참조 이미지 권한, 생성 서비스 플랜, 공개 배포 허용 확인 전에는 `approved`로 승격하지 않는다.
