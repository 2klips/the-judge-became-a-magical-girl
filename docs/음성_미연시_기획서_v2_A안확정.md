## 1. 게임 전체 플로우

```
타이틀 (마이크 연결·입력 장치 선택·실시간 dBFS 테스트 통과 후 시작 활성화)
 → 프롤로그 (고정 연출, 입력 없음)
 → [일상 파트] 챕터1: 자유 대화 노드 2개 — 호감도 적립
 → 분기점① (호감도 3구간: ≥60 / 40~59 / <40)
 → [일상 파트] 챕터2: 경로별 노드 1~2개 + 분기점② (의도 선택 → 핵심 플래그)
 → [사건 발생] 컷씬 — 적 출현, 위기 연출
 → [변신 이벤트] 음성 주문 게이트 (§4)
 → [전투 파트] STT 대화형 전투 1회, 3페이즈 (§5)
 → [수렴 파트] 챕터3: 전투 결과가 반영된 대화 노드 1개
 → 최종 분기 (호감도 × 플래그 × 전투 등급)
 → 엔딩 4종
```

**시간 예산 (데모 10~30분 대응):**
| 파트 | 짧은 시연 (노드 턴상한 4) | 긴 시연 (턴상한 6) |
|---|---|---|
| 프롤로그+일상 | 5~7분 | 10~14분 |
| 사건+변신 | 1~2분 | 1~2분 |
| 전투 (3페이즈 × 2~3턴) | 3~4분 | 4~6분 |
| 수렴+엔딩 | 2~3분 | 3~5분 |
| **합계** | **약 11~16분** | **약 18~27분** |

턴 상한은 `config.json` 값 하나로 전환한다.

## 2. 상태 모델

### 2.1 전역 상태 (게임 전체)

| 상태값 | 형 / 범위 | 갱신 시점 | 용도 |
|---|---|---|---|
| `affinity` | int 0~100, 시작 50 | 대화 턴 판정 후, 델타 -3~+3 클램프. 전투 종료 시 등급 보정(+10/+5/0) | 분기점·엔딩 판정 주축 |
| `npcEmotion` | enum `neutral/happy/shy/upset/surprised` | 매 NPC 응답 | 표정 에셋 1:1 매핑 |
| `flags` | Set&lt;string&gt; | 의도 매칭·전투 등급·주문 등급 시. **노드별 화이트리스트 안에서만** | 스토리 이벤트, 엔딩 조건 |
| `playerForm` | `normal` \| `magical` | 변신 이벤트 성공 시 1회 | UI 테마·BGM 전환, 전투 진입 조건 |
| `battleGrade` | `S` \| `A` \| `B` \| null | 전투 종료 시 1회 | 수렴 파트 대사 변형, 엔딩 보정 |
| `nodeTurn` / `totalTurn` | int | 매 사이클 +1 (노드 이동 시 nodeTurn=0) | 수렴 규칙 |
| `currentNodeId` / `history[]` | string / string[] | 분기 이동 시 | 진행 위치, 디버그 |
| `inputMode` | `voice` \| `click` | 실패 누적 시 전환, 토글 복귀 가능 | 대체 입력 경로 |
| `sttFailCount` / `llmFailCount` | int | 실패 +1, 성공 시 0 | 폴백 트리거 |

### 2.2 전투 한정 상태 (battle 노드 진입 시 생성, 종료 시 등급으로 환산 후 폐기)

| 상태값 | 형 / 범위 | 설명 |
|---|---|---|
| `momentum` (기세) | int 0~100, 시작 50 (완전 변신 시 60) | 전투의 유일한 스탯. HP 없음, 패배 없음 |
| `phaseIndex` / `phaseTurn` | int | 페이즈 진행·턴 상한 관리 |
| `enemyState` | `normal` \| `weakened` | momentum ≥ 65에서 파생 — 적 이미지 스왑 |

**불변 규칙 (v1 유지):** 상태는 오직 "판정 결과"로만 변한다. LLM은 화이트리스트 밖의 플래그를 만들 수 없고 델타는 클램프된다. 스냅샷은 분기 이동마다 `localStorage`에 저장(새로고침 복구용).

## 3. 대화 루프 (v1 확정 + 보강)

```
[대기] → ①음성 입력(PTT) → ②로컬 키워드 판정 → ③LLM 판정(미매칭 시)
       → ④연출(표정+타이핑) → ⑤상태 갱신 → ⑥분기 판정 → [대기 or 이동]
```

v1과 동일하되 다음을 확정 보강한다.

- **시작 마이크 게이트:** 게임 최초 화면은 `마이크가 연결되어야 플레이 가능해요` 타이틀의 마이크 테스트다. 권한 허용, 입력 장치 연결, 실시간 레벨 테스트를 통과하기 전에는 새 게임·이어하기 버튼을 활성화하지 않는다. 테스트 통과 뒤에는 플레이 중 클릭 모드 전환과 기존 실패 폴백을 유지한다.
- **실시간 자막:** `SpeechRecognition`의 `interimResults: true`로 플레이어 발화를 화면에 실시간 표시한다. 심사위원이 "내 말이 인식되고 있다"를 즉각 확인 — 시연 임팩트의 핵심.
- **오프라인 고정 응답:** 각 의도에 `offlineReply`(고정 대사 1줄)를 필수화한다. 로컬 모드(LLM 불능)에서 키워드 매칭 → 이 대사를 재생해 완주를 보장한다.
- **판정 우선순위(재확인):** ① intent에 `next` 있으면 즉시 이동 → ② `nodeTurn ≥ maxTurns`면 exit 조건표 강제 이동 → ③ 같은 노드 루프.
- 실패 처리: STT 같은 턴 2회 실패 → 그 턴 클릭 선택지 / 누적 5회 → `inputMode=click` 전환 / LLM 3연속 실패 → 로컬 모드 강등. (v1 §5 그대로)

## 4. 변신 이벤트 — 음성 주문 게이트 (Incantation Gate)

플레이어가 **화면에 표시된 변신 주문을 마이크로 낭독**하면 변신한다. 게임의 시그니처 장면이므로 "실패로 막히는 관문"이 아니라 **"낭독 품질로 연출 등급이 갈리는 이벤트"**로 설계한다. 진행이 멈추는 경우는 없다.

### 4.1 흐름

```
사건 컷씬 → 주문 UI 표시(주문 전문 + 마이크 안내)
 → PTT로 낭독 → 정규화 후 키워드 커버리지 채점
 → [완창]   전 키워드 매칭   → "완전 변신" 강화 연출 + 전투 시작 momentum 60 + flag: perfect_transform
 → [성공]   minMatch 이상    → 표준 변신 연출 + momentum 50
 → [미달]   재도전 안내(최대 2회) → 2회 미달 시 자동 진행(작가가 서사적 구제 연출 작성, 예: NPC가 힘을 보태줌) + momentum 50, 페널티 없음
 → 변신 컷씬(정지 일러스트 2장 + CSS 플래시/파티클 + 변신 징글) → 전투 노드 진입
```

### 4.2 채점 방식

- 정규화: 공백·문장부호 제거, NFC 정규화 → 소문자화 불필요(한국어)
- 판정: `requiredKeywords` 배열의 각 키워드가 transcript에 **부분 문자열로 포함**되는지 검사. 순서 무관 — 낭독이 조금 틀려도 관대하게
- 예: 주문(더미) "반짝이는 별의 힘이여, 지금 여기에 — 변신!" / keywords `["별", "힘", "변신"]` / minMatch 2
- 여유가 있으면 자모 분해 유사도(레벤슈타인)를 추가하되, 키워드 포함 검사만으로 데모는 충분하다
- **주문 전문을 화면에 크게 표시하는 것 자체가 소음 대책이다** — 플레이어는 읽기만 하면 되고, 읽는 발화는 인식률이 높다

### 4.3 클릭 폴백

`inputMode=click`이거나 마이크 불능 시: "주문 외우기" 버튼 → 표준 변신(성공 등급)으로 진행. 완창 보너스는 음성 전용 — 음성 플레이의 보상 차별화.

## 5. 전투 시스템 — STT 대화형 "언령(言靈) 배틀"

**결론: 지시된 방향(STT 대화로 전투 이벤트 진행)이 최적이라 판단, 대안 검토 없이 바로 설계한다.** 근거: ① 핵심 차별점(음성)과 일관되고 ② 대화 루프 엔진을 그대로 재사용해 구현 비용이 노드 1타입 추가 수준이며 ③ JRPG식 UI·이펙트 에셋 부담이 없다.

### 5.1 개념

전투는 **battle 타입의 특수 노드 1개**다. 적이 말/행동으로 압박하고, 플레이어는 **음성**으로 대응한다. HP·데미지 대신 **기세(momentum) 게이지 하나**가 오르내리고, 패배는 존재하지 않는다 — 결과는 승리의 **등급(S/A/B)** 이다. 데모에서 게임오버로 막히는 사고를 구조적으로 제거한다.

### 5.2 플레이어의 대응 3종 (매 턴 택1)

| 대응 | 입력 | 판정 | momentum 델타 |
|---|---|---|---|
| **주문 시전 (spell)** | 화면에 표시된 페이즈별 주문을 낭독 | 시작 테스트로 보정한 dBFS 허용 범위 → §4.2 키워드 채점 | 크리티컬(전부) +25 / 성공(minMatch↑) +15 / 내용·음량 불발 0 |
| **자유 대응 (freeform)** | 설득·도발·격려 등 자유 발화 | LLM 판정 (전투용 JSON 스키마) | -5 ~ +10 (LLM이 산정, 클램프) |
| **버티기 (guard)** | "막아", "버텨" 등 키워드 | 로컬 키워드 | 고정 +3, 실패 없음 (안전 선택지) |

- 주문은 **페이즈마다 다른 문구**를 작가가 작성한다 — 전투의 "손맛"이자 낭독 스킬 요소
- 브라우저가 측정하는 값은 물리 음압(dB SPL)이 아니라 디지털 입력 레벨 `dBFS`다. 시작 테스트의 평소 발화를 기준으로 사용자별 허용 범위를 만든다.
- 주문 음성이 너무 작거나, 너무 크거나, clipping이 발생하면 실패한다. 첫 음량 실패는 턴을 소모하지 않고 피드백 뒤 같은 주문을 다시 시도한다. 같은 주문에서 두 번째 음량 실패는 `momentum +0` 불발로 턴을 소모한다.
- 음량 판정은 전투의 `spell`에만 적용한다. 자유 대응과 클릭 주문은 기존 규칙을 유지한다.
- 자유 대응이 "말로 싸운다"는 판타지와 AI 어필의 핵심: LLM이 발화의 맥락(적의 약점을 찌르는 설득인지, 빗나간 소리인지)을 평가하고 적의 반응 대사를 생성한다
- 클릭 폴백 3버튼: [주문 시전(성공 등급 고정)] [정의된 대응 대사 택1] [버티기]

### 5.3 페이즈 구조와 종료

- 전투 1회 = **페이즈 3개**, 페이즈당 턴 상한 2~3
- 페이즈 전환: `momentum ≥ 페이즈별 임계(예: 60/70)` 도달 시 즉시 전환(우세 연출) **또는** 턴 상한 도달 시 강제 전환(고전 연출) — 대화 노드의 수렴 규칙과 동일한 원리
- 최종 페이즈 종료 시 등급 산정: `momentum ≥ 80 → S(완승)` / `≥ 55 → A(신승)` / 그 외 `B(고전 끝에 승리)`
- momentum 바닥은 20으로 클램프 — 연속 불발이어도 분위기만 나빠질 뿐 진행은 된다

### 5.4 등급의 효과

| 등급 | 호감도 보정 | 플래그 | 서사 효과 |
|---|---|---|---|
| S | +10 | `battle_S` | 수렴 파트에서 NPC 대사 강화, HIDDEN 엔딩 조건 후보 |
| A | +5 | `battle_A` | 표준 |
| B | 0 | `battle_B` | 수렴 파트에서 만회 대사 1회 제공 |

엔딩의 1차 조건은 여전히 호감도×플래그다. 전투 등급은 **보정과 연출 변형**에만 쓴다 — 조건을 겹겹이 쌓으면 심사위원이 GOOD 엔딩을 못 본다.

### 5.5 전투 연출 (구현 관점)

momentum 게이지(호감도 게이지 스킨 교체 재사용), 적 이미지 2상태 스왑(`normal/weakened`), CSS 화면 셰이크·플래시, Canvas 2D 파티클 1모듈, 전투 BGM 크로스페이드. 신규 시스템이 아니라 **기존 연출 모듈의 파라미터 변경**으로 처리한다.

### 5.6 LLM 전투 판정 스키마

```json
{ "reply": "적 또는 나레이션 대사 (80자 이내)",
  "intent": "persuade | taunt | encourage | other",
  "momentumDelta": -5,
  "narration": "짧은 상황 묘사 (선택)" }
```

시스템 프롬프트에 페이즈별 `llmContext`(적의 상태·약점·이번 페이즈의 압박 내용)를 주입한다. 대화 판정과 같은 프록시·같은 타임아웃(4초)·같은 폴백 규칙.

## 6. 분기 구조와 엔딩 (v1 갱신)

- 분기점 3개(중간 2 + 최종 1) + 변신 게이트 + 전투 등급 분기(연출 한정) / 대화 노드 8~10 + 컷씬 2 + 전투 1 + 엔딩 4

| 엔딩 | 조건 | 비고 |
|---|---|---|
| GOOD | `affinity ≥ 70 && flags.promise` | 전투 보정 포함 도달 가능하게 수치 설계 |
| NORMAL | `affinity ≥ 40` | |
| BAD | `affinity < 40` | "관계 실패"이지 게임 실패가 아님 — 전투는 이미 승리했음 |
| HIDDEN | `flags.perfect_transform && flags.battle_S` | **컷 1순위.** 음성 플레이 마스터 보상 |

## 7. 수렴 규칙 (v1 유지, 전투 확장)

1. 대화 노드 턴 상한 4~6 → `exitOnMaxTurns` 강제 이동 (스토리 대사로 포장)
2. LLM이 노드 `objective`로 수렴을 주도, freeform 3연속 시 유도 질문 강제 삽입
3. 전역 상한 `totalTurn = 45~55` → 최종 분기 점프
4. **전투도 같은 원리:** 페이즈 턴 상한 + 임계 도달 즉시 전환. 전투 전체 상한 9턴
5. 실패 처리 체계는 §3과 동일 (STT/LLM/오프라인 3단 폴백)

### 8.3 LLM 호출 계약 (대화 판정)

- PTT release → Worker `/voice/realtime` 1회 → `gpt-realtime-2.1-mini`가 transcript와 판정 function call 반환 → 로컬 intent 우선 확인 → 로컬 미매칭이면 검증된 Realtime 판정 적용. 일반 UI에는 transcript 원문을 표시하지 않는다.
- 요청: 페르소나 시트 + 노드 `objective`/`llmContext` + 상태 요약(호감도 구간·플래그) + 최근 2~3턴 + 플레이어 발화
- 응답(responseSchema 강제): `{ reply, intent(노드 정의 목록 | "freeform"), affinityDelta(-3~3), emotion, flags(allowedFlags 내) }`
- 실패 사다리: 4초 타임아웃 → 1회 재시도 → `fallbackReplies` + 중립 판정 → 3연속 실패 시 로컬 모드

### 8.4 Codex 운용 — 마일스톤 (각 단계가 "실행 가능한 게임")

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| M1 | 노드 엔진 + JSON 로더 + **클릭 모드만으로 완주** | 더미 시나리오로 타이틀→엔딩 도달 |
| M2 | STT(PTT·실시간 자막) + 로컬 키워드 판정 | 음성으로 M1 시나리오 완주 |
| M3 | GPT/Gemini STT 전환형 Workers 프록시 + LLM 판정 + 3단 폴백 | 두 STT 공급자 각각 MVP-1 대화 통과, 네트워크 차단 상태에서도 완주 |
| M4 | 변신 게이트 + 전투 러너 + momentum UI | 더미 전투 S/A/B 3등급 재현 |
| M5 | 연출(표정·파티클·BGM) + 실제 에셋·시나리오 통합 | 본편 완주 |
| M6 | 리허설·디버그 패널 마감·시연 영상 녹화 | 제출물 완성 |

Codex에는 **본 문서의 해당 절 + 저장소 구조 + 완료 기준**을 작업 단위로 전달한다. 한 번에 전체가 아니라 마일스톤 단위로 지시하고, 각 단계에서 반드시 실행 확인 후 다음으로 넘어간다.
