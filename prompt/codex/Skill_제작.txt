# Skill 설계 원칙

- `SKILL.md`는 프로젝트 전체 기획서를 복제하지 않는다.
- 프로젝트의 현재 기준 문서를 먼저 읽도록 라우팅한다.
- 핵심 절차와 판단 규칙만 `SKILL.md`에 둔다.
- 상세 스키마와 템플릿은 `references/`로 분리한다.
- 반복적이고 결정적인 검증만 `scripts/`로 분리한다.
- README, 설치 가이드, 변경 이력 같은 불필요한 파일을 만들지 않는다.
- SKILL.md는 500줄 미만으로 유지한다.
- 명령형 문장으로 작성한다.
- planning 요청에서는 코드를 수정하지 않는다.
- implementation 요청에서만 관련 로컬 파일을 수정한다.
- 기준 문서 변경이 필요하면 임의 수정하지 않고 변경 제안으로 분리한다.

# 반드시 보호할 프로젝트 계약

- A안 아키텍처

- 클릭·오프라인 완주

- 전투는 패배가 아닌 S/A/B 등급
- JSON next 참조 무결성
- 모든 intent의 clickLabel과 offlineReply
- 캐릭터 대사 80자 이하
- 에셋 파일명 계약
- 총 에셋 30MB 이하
- GitHub Pages 정적 배포
- API 키 클라이언트 노출 금지


# 생성 절차

1. `skill-creator`의 `init_skill.py`로 초기화한다.
2. 필요한 리소스만 생성한다.
3. `SKILL.md`와 references를 작성한다.
4. agents/openai.yaml이 SKILL.md와 일치하는지 확인한다.
5. `quick_validate.py`를 실행한다.
6. 검증 오류를 수정하고 다시 실행한다.
7. 실제 프로젝트 요청 예시 3개로 정적 검토한다.
8. 이 작업에서는 subagent를 사용하지 않는다.
