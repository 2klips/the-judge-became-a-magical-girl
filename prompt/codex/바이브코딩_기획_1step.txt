# 작업 모드

바이브 코딩을 위한 개발 문서 체계 구축.
아직 게임 코드는 구현하지 않는다.


# 기준 문서

다음을 UTF-8로 모두 읽는다:

- docs/음성_미연시_기획서_v2_A안확정.md
- docs/별첨1_스토리_작가_가이드라인.md
- docs/별첨2_에셋_제작_가이드라인.md

현재 저장소 전체 파일 구조도 확인한다.


# 목표

확정된 기획을 Codex가 M1~M6 단위로 구현할 수 있도록,
중복이 적고 추적 가능한 개발 문서 체계를 만든다.

기획을 다시 쓰는 작업이 아니다.
기획 내용을 개발자가 실행할 수 있는 계약으로 변환하는 작업이다.


# 확정사항

다음은 변경하지 않는다:

- A안: LLM 자유 대화 + 스탯 수렴
- STT 중심, 클릭·로컬 완주 폴백
- 변신 주문 게이트
- 3페이즈 언령 배틀
- TypeScript + Vite + Vanilla DOM/CSS
- zod 런타임 검증
- Cloudflare Workers 프록시
- GitHub Pages 배포
- M1~M6 순서
- MVP와 컷 우선순위
- 시나리오 JSON 및 에셋 파일명 계약

# 품질 규칙

- 기존 세 기획 문서는 수정하지 않는다.
- 동일 설명을 여러 새 문서에 복제하지 않는다.
- 새 문서는 기준 문서의 절을 링크 또는 파일명+제목으로 참조한다.
- 확정 내용과 Codex가 추론한 내용을 구분한다.
- 추론한 내용에는 “제안” 또는 “가정” 표시를 붙인다.
- 구현에 영향을 주는 모순과 미결정 사항을 목록화한다.
- 불필요한 README형 문서를 추가하지 않는다.


# 검증

작성 후 다음을 확인한다:

1. 모든 문서 링크와 경로가 유효한가
2. M1~M6 완료 기준이 기존 기획과 일치하는가
3. JSON·에셋 계약이 별첨과 충돌하지 않는가
4. API 키가 문서에 노출되지 않았는가
5. 같은 규칙이 여러 파일에 모순되게 복제되지 않았는가
6. AGENTS.md가 행동 규칙 중심으로 짧게 작성됐는가
