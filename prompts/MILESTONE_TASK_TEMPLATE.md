# Codex 마일스톤 작업 프롬프트

아래 대괄호를 채워 새 작업에 사용한다. 한 번에 마일스톤 하나만 요청한다.

```text
# 작업 모드

[M1|M2|M3|M4|M5|M6] 구현.
이 마일스톤 밖 기능은 구현하지 않는다.

# 먼저 읽을 문서

다음을 UTF-8로 읽고 지시 우선순위를 따른다:

- AGENTS.md
- docs/dev/PROJECT_MAP.md
- docs/dev/IMPLEMENTATION_SPEC.md
- docs/dev/MILESTONES.md의 [M?] 절
- docs/dev/QA_AND_DEMO.md의 관련 테스트
- [이 단계에 필요한 기준 문서 절/별첨]
- [보안/에셋/결정 문서]

현재 저장소 구조와 변경 상태를 확인한다. 기존 사용자 변경을 보존한다.

# 확정 입력

- 대상 마일스톤: [M?]
- 패키지 관리자: [npm 등]
- 실행 환경: [OS / Chrome / Node]
- Pages 저장소 이름/base: [값 또는 이번 단계 N/A]
- Git/GitHub 게시: [필요/불필요, owner/repository/visibility/branch]
- 승인된 관련 결정: [DEC-...]
- 사용할 시나리오/에셋: [더미/실제, 경로]
- 추가 제약: [...]

# 목표

[MILESTONES.md 해당 목표를 한 문장으로 복사]

# 구현 범위

[해당 마일스톤 구현 범위를 참조. 이번 작업에서 더 좁힌 범위가 있으면 기입]

# 비범위

- 다음 마일스톤 기능
- 기준 문서의 컷 항목
- 관련 없는 리팩터링
- 승인되지 않은 스키마/의존성/에셋 ID 추가
- [...]

# 실행 방식

1. 관련 계약과 현재 코드를 대조한다.
2. 모순·차단 미결정이 있으면 구현 전 보고한다. 안전한 제안은 “제안”으로 표시한다.
3. 작은 실행 가능 단위로 구현한다.
4. 상태·분기·판정 로직을 외부 API와 분리한다.
5. 자동 테스트와 오류 진단을 함께 작성한다.
6. docs/dev/DECISIONS.md는 새 결정이 생긴 경우만 갱신한다.
7. docs/assets/AI_PRODUCTION_LOG.md에 이번 AI 작업 기록을 추가한다.
8. 마일스톤에 Git/GitHub 게시가 포함되면 자동·수동 검증 통과 뒤 staging 범위와 비밀정보를 확인하고 commit·push한다.

# 완료 검증

반드시 실행:

- npm run check
- npm test
- npm run build

추가 자동 검증:

- [MILESTONES.md의 해당 자동 검증]

수동 플레이:

- [QA 테스트 ID]

Git/GitHub 검증:

- [해당 시 QV 테스트 ID, 아니면 N/A]

# 중단 조건

- 확정사항 변경이 필요함
- 실제 비밀값 또는 외부 계정 권한이 필요함
- 사용자 선택에 따라 아키텍처/데이터 계약이 달라짐
- 기존 변경과 안전하게 병합할 수 없음

중단 조건이 아니면 합리적 가정으로 진행하고 가정을 명시한다.
```
